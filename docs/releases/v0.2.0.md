# ArborVault 0.2.0 — reliability and evaluation preview

Released 2026-11-13. This remains an independent project inspired by structured retrieval,
not an official IBM implementation or verified STAIR reproduction.

## Changes

- Retained document revisions and historical trees keep citations resolvable after updates.
  Full deletion removes all revisions; re-ingestion creates a fresh document identity.
- Numbered transactional migrations preserve the current v0.1 tree. PostgreSQL RLS,
  scoped foreign keys and a restricted runtime role add isolation checks at the database.
- Explicit read/write/delete permissions, hashed credential files, next-request revocation,
  cursor pagination, quotas and consistent query snapshots strengthen the API contract.
- A separate internal parser container runs disposable workers with resource/deadline limits.
  It has no database credentials, persistent volume, published port or external network.
- Backup/restore verification, upgrade instructions, structured request logs, pinned base
  images and CI for both PostgreSQL tests and the complete Compose service are included.
- Public Docs v1 adds eight licensed source files, 85 content sections and 60 draft
  English/Italian questions, split into 16 development and 44 test queries. Corpus hashes,
  licenses, evidence labels, validation and BEIR-style export are included.

## Compatibility

Read the [upgrade guide](../upgrade-v02.md) before starting an existing installation.
Credentials now require explicit permissions, the API must use the restricted database
login, and Compose adds a parser service. Existing document IDs and the latest v0.1
content are preserved; older discarded v0.1 revisions cannot be reconstructed. Do not run
v0.1 against the migrated schema. The `/v1` route family remains; history routes and
pagination metadata are additive. Review clients that assumed one list response was complete.

## Validation record

- 38 pytest cases passed on Linux/Python 3.12 with PostgreSQL 17, including actual RLS,
  legacy migration/checksum checks, concurrent-update snapshot consistency, authorization,
  malformed credential reload, revision retention, parser failure and dataset integrity.
- Ruff lint and formatting checks passed; the third-party corpus is deliberately excluded
  from formatting so its original bytes and hashes are retained on every platform.
- Live Compose test passed: ready state, isolated parsing, idempotent ingest, second revision,
  historical read, history pagination, current query citations and full deletion.
- A custom-format backup was restored into a new temporary database, with schema version 3
  and expected document/revision/node counts. The live database was not overwritten.
- Dependency audit reported no known vulnerabilities in the installed test/evaluation
  environment at validation time. The unpublished project package itself has no advisory
  entry; this does not audit application logic or operating-system/container packages.
- Publication checks include tracked-content scanning and manual review of data provenance.
  Source corpora are public upstream documentation with recorded licenses and revisions.

The test client emits one upstream Starlette/httpx deprecation warning. Migration, API,
parser and PostgreSQL tests still pass; this warning is recorded rather than hidden.

## Retrieval findings and limitations

At k=5 and 512 whitespace words of returned context, test section Recall@5 was **0.5833**
for navigation/auto, **0.4444** for PostgreSQL lexical and **0.9167** for MiniLM dense
sections. No-answer abstention was 0.125 for local paths and 0 for untuned dense retrieval.
See the [protocol and raw reports](../evaluation.md). The dense baseline performs better
on this small dataset; the release makes no superiority or production-readiness claim.

Labels are assistant-authored drafts awaiting independent review. The corpus is limited
to developer documentation; model inputs may be truncated and the word budget is not a
token budget. There is no generated-answer evaluation or representative load test.
Next work should prioritize annotation review, a new held-out evaluation set, abstention,
lazy tree loading and shared quotas before broader adoption by agent applications.
